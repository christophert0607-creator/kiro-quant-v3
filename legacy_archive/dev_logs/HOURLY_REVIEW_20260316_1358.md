## 2. Issue Analysis

### Issue 1: Input Dimension Drift (HIGH Priority)

**Symptoms**:
```
ModelManager | WARNING | Input dim drift detected: model=24 new=22. Rebuilding channels.
ModelManager | WARNING | Input dim drift detected: model=22 new=24. Rebuilding channels.
```

**Root Cause**: 
- US symbols (AAPL, TSLA, NVDA) → 24 features
- HK symbols (09988, 03690, 00700) → 22 features
- Shared model across all symbols causes constant rebuilds

**Impact**: 
- Performance degradation (model rebuilding on every symbol switch)
- Excessive logging noise
- Potential latency in trading decisions

**Analysis**:
- The `ModelManager._ensure_model_input_dim()` in `v3_pipeline/models/manager.py` detects mismatch and rebuilds LSTM channels
- This is triggered because `DataPreparer` produces different feature counts per data source

### Issue 2: MFI_14 Indicator Warning (LOW Priority)

**Symptoms**:
```
TechnicalIndicatorGenerator | WARNING | Fallback indicator 'MFI_14' was all-NaN; filled with neutral default 50.0
```

**Root Cause**: Money Flow Index (MFI) requires volume data. Some HK stock data from eastmoney may have zero/invalid volume, causing MFI calculation to return NaN.

**Impact**: Non-critical, just log noise. Fallback works correctly.

### Issue 3: Yahoo Delisted Warnings (INFO only)

**Symptoms**:
```
$00700: possibly delisted; no price data found (period=5d)
```

**Root Cause**: Yahoo Finance doesn't support HK stocks with $ prefix. This is expected behavior - system correctly falls back to eastmoney.
